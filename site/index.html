How it works

Track every hire like a parcel

Each new worker becomes a case that moves through five stops. The agent does the legwork between stops. A manager signs off at the ones that matter.

  1. 1
    Slack

    Drop the hiring sheet

    Upload this week's spreadsheet in any layout, or start one case by name. The agent reads the rows and opens a case per person.

  2. 2
    Email

    Collect the details

    Each hire gets a welcome email asking for a CV, LinkedIn and a short questionnaire. Follow-ups ask only for what is still missing.

  3. 3
    On your GB10

    Propose a plan

    A local model pulls experience out of the CV with quoted evidence. Your policy picks the track, modules and daily stop targets.

  4. 4
    Slack

    Manager approves

    The plan arrives with its evidence and any conflicts. One tap approves it, and the worker gets their two-week plan by email.

  5. 5
    Slack

    Joined and welcomed

    The agent sends the Slack invite, waits until the person has really joined, then welcomes them and answers their questions.

Stop 2 · Intake

Asks only for what's missing

New hires aren't in Slack yet, so email is the channel. Replies are matched by thread and sender. A duplicate delivery is ignored, and a reply from the wrong address is held for a manager.

Nothing in an email can approve, invite or change permissions.

Monitoring

One board for the whole wave

Ops leads see every case, the evidence behind each plan, held emails and invitations that were sent but not yet accepted. It has no buttons on purpose: every decision carries a manager's Slack identity.

Invite sent and joined are tracked separately.

Built for real HR data

Guardrails, not good intentions

Data

AI stays on your hardware

CVs, answers and plans are read by a model running on your GB10. Slack and your mail provider carry the messages, as they already do today.

Authority

Managers approve, always

Only listed managers can start cases, approve plans or send invites. The status board has no write actions at all.

Evidence

Every fact is quoted

A fact survives only if its quote appears word for word in the CV or the answers. A garbled model reply becomes a review item, never a guess.

Untrusted input

CVs are data

Instructions hidden in a CV or an email are flagged to the manager and ignored. Quoted email history is stripped before anything is read.

Privacy

One case per person

Every record and every model session is scoped to one hire. A new hire can ask about their own plan and nobody else's.

Reliability

Sent once, or flagged

Every email and invite has a stable key. If a send's outcome is unknown, it is shown to a manager instead of being retried blindly.

Assumptions and sources · this is an estimate

Cloud prices. Standard list prices per million tokens for OpenAI's GPT-5.5 ($5 in, $30 out), GPT-5.4 ($2.50 / $15) and GPT-5.4 mini ($0.75 / $4.50), as summarized by BenchLM, Oct 1 2026. Prompt caching and batch discounts can lower cloud bills; they are not applied here.

Hardware. Dell Pro Max with GB10, 128 GB unified memory, 4 TB SSD, listed at $9,007 on Dell.com (October 2026). Smaller-storage configurations cost less. Paid once, counted in full in the 3-year total.

Throughput. About 3 seconds per model call, measured on one GB10 running Qwen through NemoClaw during the build. Each unit is planned at 50% utilization with calls handled one at a time, which is conservative; batched serving fits more. One spare unit is always added.

Power. 200 W average draw per unit, around the clock, at $0.15 per kWh. Rack space, staff time and the onboarding software itself are not included on either side.

Workload. 30 calls per hire with 12,000 input and 1,000 output tokens each, so about 360k tokens in and 30k out. Reasoning models often bill extra hidden output tokens, which would raise the cloud side.

Scenario. "50,000 seasonal hires" describes a national parcel carrier's peak season. Fleetwing Express is fictional and no real company's figures are used.

Installation

From box to first hire in an afternoon

You buy the hardware once and keep it. Onboarding Buddy runs as one service next to a local model, connects to the Slack and email you already use, and reads your training rules from a file your ops team owns.

  1. Rack the box

    Start with a Dell Pro Max with GB10 or any NVIDIA GB10 system, sized with the calculator above. Plug it into your network like any server. Larger fleets add units, not contracts.

    # check the GPU and unified memory
$ nvidia-smi --query-gpu=name,memory.total --format=csv

  2. Start the local model

    NemoClaw launches a sandboxed OpenClaw agent backed by a local model: Qwen for the main agent, or Nemotron Nano as a lighter option. No API keys, no per-token billing.

    $ nemoclaw launch gb10-agent
# one isolated session per new hire, e.g.
# onboarding-FW-001-extract, onboarding-FW-001-chat

  3. Install Onboarding Buddy

    One Node service with a built-in SQLite database. State lives outside the app folder, so updates and restarts never lose a case.

    $ git clone https://github.com/lydakis/OnboardingBuddy
$ cd OnboardingBuddy && npm ci

  4. Connect Slack and email

    Install the Slack app from the included manifest at the organization level, so the agent can send invitations. Point it at an onboarding inbox. List the managers who may approve.

    # ~/.config/onboarding-buddy/env  (chmod 600)
OB_SLACK_MODE=socket
OB_EMAIL_MODE=agentmail
OB_LLM_MODE=nemoclaw
OB_MANAGER_SLACK_IDS=U0MANAGER1,U0MANAGER2
OB_NEW_HIRE_CHANNEL=C0NEWCOURIERS

  5. Load your training policy

    Tracks, modules, required evidence and daily stop targets live in one JSON file with a rule ID on every decision. Change the policy and the next plan follows it.

    { "id": "experienced",
  "rule": "R-TRACK-1: At least 2 years of parcel or
           route delivery experience plus a driver's
           license qualifies for the Experienced track.",
  "minParcelYears": 2, "requiresLicense": true,
  "rampPctByDay": [0,0,0,50,60,70,80,90,95,100] }

  6. Check, then go live

    The readiness check confirms Slack scopes, the inbox and the model without sending anything. Then start the service and drop your first hiring sheet in Slack.

    $ npm run live:check   # read-only, sends nothing
$ npm start
What you keep

The hardware, the model, every case record and the audit trail. Nothing to cancel when the season ends.

What you bring

A Slack organization, an email inbox for onboarding, and your training rules.

What it leaves out

Offer letters, identity checks, payroll and HR records stay in the systems you already run.
